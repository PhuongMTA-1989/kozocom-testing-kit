# Input JSON Schema — Checklist Workbook

One JSON file, either a top-level array of items or an object with an
`items` array — both are accepted.

```json
{
  "items": [
    {
      "screen": "Coupon Issuance",
      "check_point": "Initial Display",
      "pattern": "Customer has registered coupons",
      "expected_result": "Customer info, issue date, expiry date, and the assigned-coupon list are displayed (valid = white background, expired/deleted/used = pink background); coupon, amount, and remarks stay empty",
      "highlight": false
    },
    {
      "screen": "Coupon Issuance",
      "check_point": "Input",
      "pattern": "Remarks field: enter 251 characters",
      "expected_result": "Only 250 characters are shown (maxLength=250)",
      "highlight": false
    },
    {
      "screen": "Coupon Issuance",
      "check_point": "Input",
      "pattern": "Amount (fixed-amount coupon selected)",
      "expected_result": "Editable (half-width alphanumeric, maxLength=10)",
      "highlight": true
    }
  ]
}
```

## Fields (all required except `highlight`)

| Key | Excel column | Notes |
|---|---|---|
| `screen` | A — Screen / Process | Name of the screen, batch job, or process block. Consecutive items with the same `screen` are grouped together: the cell is vertically merged and the `No` counter restarts at 1 for each new screen. **Order items by screen** — don't interleave screens. |
| `check_point` | C — Check Point | The aspect being checked within that screen (e.g. `Initial Display`, `Input`, `Search`, `Register/Update`, `Row selection`). Consecutive items with the same value are vertically merged, same as `screen`. |
| `pattern` | D — Pattern | The specific condition/case being tested under that check point. |
| `expected_result` | E — Expected Result | The concrete, verifiable expected behavior for that pattern. |
| `highlight` (optional) | whole row | Set `true` to shade the row light green — use sparingly, for patterns that need extra reviewer attention (newly added, high-risk, or easy to overlook). Defaults to `false`. |

## Numbering

Column `B` (`No`) is generated by the renderer, not supplied in the JSON —
it restarts at `1` every time `screen` changes value, matching the source
layout where each screen/process block has its own 1-based sequence.
